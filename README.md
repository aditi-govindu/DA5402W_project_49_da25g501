## 1. Project Overview

With the rapid proliferation of Large Language Models (LLMs) like GPT-4, Claude, ChatGPT, and Bard, distinguishing between human-authored journalism and synthetically generated text has become essential for media authenticity, academic integrity, and combating misinformation.

This repository implements a **production-grade, end-to-end Machine Learning Operations (MLOps) system** designed to classify news articles and texts into:
1. **`AI-generated` (Class 1)**: Content generated by generative AI / LLMs.
2. **`Human-written` (Class 0)**: Authentic human-authored journalistic text.

The system incorporates data engineering with **Apache Spark**, workflow orchestration with **Apache Airflow**, deep learning with **PyTorch (BiLSTM + Self-Attention)**, experiment tracking with **MLflow**, data/model versioning with **DVC**, real-time containerized serving with **FastAPI & Docker**, observability via **Prometheus & Grafana**, and automated verification using **GitHub Actions CI/CD**.

## 5. Model Architecture & Data Engineering Details

### 5.1 Why Apache Spark for Data Engineering?
Natural language processing at scale requires processing millions of text articles with variable lengths, vocabulary sizes, and lexical statistics. Apache Spark (PySpark) provides:
- Distributed tokenization and regular-expression based text sanitization.
- Parallelized feature extraction (character length, token frequency, Type-Token Ratio / Lexical Diversity).
- Distributed stratified splitting into Parquet files with snappy compression for high I/O throughput.

### 5.2 PyTorch Deep Learning Model (`BiLSTMAttentionClassifier`)
The deep learning architecture combines sequence modeling with linguistic feature fusion:
1. **Embedding Layer**: Projects input token IDs into a dense $d=128$ dimensional semantic space.
2. **Bidirectional LSTM (2 Layers)**: Captures bidirectional temporal dependencies and contextual flow of both preceding and succeeding tokens.
3. **Additive Self-Attention**:
   $$\text{score}(h_t) = \tanh(W_a h_t + b_a)$$
   $$\alpha_t = \frac{\exp(\text{score}(h_t)^\top v_a)}{\sum_{j} \exp(\text{score}(h_j)^\top v_a)}$$
   $$\text{Context Vector } c = \sum_{t=1}^T \alpha_t h_t$$
4. **Linguistic Feature Fusion**: Fuses the attention context vector with normalized statistical features ($char\_length$, $word\_count$, $lexical\_diversity$, $uppercase\_ratio$, $punctuation\_density$).
5. **Classification Head**: Multi-layer perceptron with Layer Normalization, ReLU, Dropout ($p=0.3$), and Sigmoid output.

## 6. Quick Start & Execution Guide

### 6.1 Prerequisites
- Python 3.9+
- Docker & Docker Compose (optional for containerized deployment)

### 6.2 Local Environment Setup
```bash
# 1. Clone repository
git clone https://github.com/aditi-govindu/mlops-final-term-project.git
cd mlops-final-term-project

# 2. Create virtual environment
python3 -m venv venv
source venv/bin/activate

# 3. Install dependencies
pip install --upgrade pip
pip install -r requirements.txt
```

### 6.3 Run the Pipeline via Standalone Scripts
You can execute the entire pipeline with a single `make` command:
```bash
make pipeline
```

Or execute individual stages:
```bash
# Step 1: Data Ingestion & Schema Validation
python3 src/data/ingest.py

# Step 2: Feature Engineering & Preprocessing (or via Spark: python3 src/data/spark_preprocess.py)
python3 src/data/preprocess.py

# Step 3: Train Baseline & PyTorch Models with MLflow Tracking
python3 src/models/train.py

# Step 4: Evaluate Models & Generate Confusion Matrices / ROC Curves
python3 src/models/evaluate.py

# Step 5: Run Statistical Data Drift Monitoring
python3 src/monitoring/drift_detector.py
```

### 6.4 Launch MLflow Experiment Tracking UI
```bash
mlflow ui --host 0.0.0.0 --port 5000 --backend-store-uri sqlite:///mlruns.db
```
Open **[http://localhost:5000](http://localhost:5000)** in your browser to inspect runs, compare hyperparameters, and view loss curves.

## 10. Viva Examination & Architectural Defense

During the viva evaluation, you may be asked the following questions:

1. **Why use both Apache Airflow and Apache Spark?**
   - *Airflow* is an orchestration engine that manages workflow dependencies, retries, scheduling, and alerting.
   - *Spark* is a distributed computing engine that processes large-scale text transformations, distributed tokenization, and feature engineering across worker nodes.
2. **Why use a PyTorch BiLSTM with Attention instead of just a linear baseline?**
   - Linear baselines (TF-IDF + Logistic Regression) treat text as a bag of n-grams, losing word order and long-range semantic coherence.
   - The PyTorch BiLSTM models sequential context in forward and backward directions, while the Self-Attention mechanism dynamically weights critical discourse markers characteristic of AI-generated vs human writing.
3. **How does Data Drift detection work in production?**
   - We utilize the two-sample Kolmogorov-Smirnov (KS) test on continuous linguistic metrics (Type-Token Ratio, average word length, punctuation density) and Population Stability Index (PSI) on prediction probabilities to detect covariate and prediction drift before model degradation occurs.
4. **How is reproducibility ensured?**
   - Central YAML configuration (`config/config.yaml`), deterministic seed pinning (`set_seed(42)`), containerization (`Dockerfile` and `docker-compose.yml`), and versioned data pipelines (`dvc.yaml`).
